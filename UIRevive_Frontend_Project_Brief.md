# UIRevive --- AI Website UI Improvement Platform

## Project Overview

**Project idea:** A frontend-only prototype of an AI-powered platform
that helps users understand how the UI/UX of an existing website can be
improved without making every website look like the same AI-generated
template.

**Current scope:** Frontend plus one thin server-side API route that
calls Ollama (using the user's Ollama API key). Do not build a database,
separate server, crawler, or real website-scanning service in this phase.

The prototype should demonstrate the complete user journey. The report
is generated by an Ollama model from the submitted URL, with mock data
as a fallback if the API call fails. Real website crawling/screenshot
analysis can be added in a later phase.

## Problem Statement

Many websites have UI problems such as inconsistent spacing, weak visual
hierarchy, poor typography, confusing layouts, and inconsistent colors.
Website owners and developers may know that a website needs improvement
but may not know exactly what to change or why.

At the same time, many AI-generated website designs can look repetitive.
UIRevive aims to present improvement suggestions that respect the
existing website's visual identity rather than simply applying a generic
design.

## Target Users

-   Freelance web developers
-   UI/UX designers
-   Web design agencies
-   Small business owners
-   People who want to improve an existing website

## Main User Journey

1.  The user opens the UIRevive landing page.
2.  The user pastes a website URL into the input field.
3.  The user clicks **Analyze Website**.
4.  The application displays a short, animated scanning/loading
    experience.
5.  The application opens a sample analysis report.
6.  The user reviews the overall score and identified UI issues.
7.  The user explores practical improvement recommendations.
8.  The user views a before-and-after concept for an example section.

## MVP Features

### 1. Landing Page

-   Clear explanation of what UIRevive does.
-   Website URL input field.
-   Prominent **Analyze Website** button.
-   Modern hero section and concise feature highlights.

### 2. URL Input

-   Allow the user to enter a website URL.
-   Perform basic frontend validation for an empty or incorrectly
    formatted URL.
-   In this frontend-only version, the URL is used as display/demo input
    only. It is not fetched or scanned.

### 3. Scanning Experience

-   Show animated progress or scanning steps after the user submits a
    URL.
-   Use a short simulated delay and then display the demo report.
-   Make it clear that the current analysis is a prototype/demo, not a
    real scan.

### 4. Analysis Report

Show a sample report containing: - Overall UI score. - Visual
hierarchy. - Typography. - Color consistency. - Spacing and alignment. -
Layout clarity. - Mobile responsiveness.

Use realistic sample values and explanations. Do not claim that these
values were measured from the submitted website.

### 5. UI Issues and Recommendations

Display sample issues with: - UI element or area. - Identified
problem. - Why it matters. - Severity (Low, Medium, or High). -
Suggested improvement.

### 6. Improvement Preview

-   Provide an example before-and-after comparison.
-   Show how a selected section could be improved.
-   Explain the design changes.
-   Use sample preview content rather than attempting to modify the
    submitted website.

### 7. Responsive Interface

-   Support mobile, tablet, laptop, and desktop screen sizes.
-   Keep navigation and report content usable on smaller screens.

## Design Direction

-   Modern, minimalistic, sleek interface.
-   Professional SaaS product feel.
-   Clean typography and clear visual hierarchy.
-   Subtle animations and transitions.
-   Avoid excessive gradients, glowing effects, and unnecessary
    decoration.
-   Use a consistent spacing system and reusable components.
-   The UI should feel distinctive, not like a generic AI dashboard
    template.

## Suggested Pages

-   `/` --- Landing page
-   `/analyze` --- URL submission and scanning experience
-   `/report` --- Demo analysis report and recommendations

The routes may be adjusted if the AI code editor recommends a simpler
structure, but the user journey must remain clear.

## Suggested Frontend Technology

-   Next.js
-   TypeScript
-   Tailwind CSS
-   Lucide icons
-   React state for interactions
-   Local mock JSON/TypeScript data for sample analysis results

Use the existing project setup if one already exists. Do not
unnecessarily replace dependencies or restructure the project.

## Important Technical Constraints

-   Frontend plus a single Next.js API route (e.g. `/api/analyze`) that
    proxies requests to Ollama.
-   **Ollama integration is in scope for this phase.** The API key is
    read from `OLLAMA_API_KEY` in `.env.local` (git-ignored). Optional:
    `OLLAMA_BASE_URL` (default `https://ollama.com`) and `OLLAMA_MODEL`.
-   Never hard-code the API key, expose it to the browser (no
    `NEXT_PUBLIC_` prefix), or commit it. Do not ask the user to paste
    it into the UI. Provide a `.env.example` with a placeholder.
-   No database or user accounts.
-   No real website scraping, crawling, screenshot capture, or DOM
    inspection. The model only receives the submitted URL, so label
    results as AI-generated estimates, not measured findings.
-   The model must return JSON matching the TypeScript report types;
    validate it and fall back to local mock data on error.
-   Show loading and error states for the API call.

## Definition of Done

The prototype is complete when a user can:

1.  Open the landing page.
2.  Enter a website URL.
3.  Submit the URL and see basic validation.
4.  View an animated scanning state.
5.  Reach a sample analysis report.
6.  Review UI scores, issues, and recommendations.
7.  View an example before-and-after improvement.
8.  Use the application comfortably on mobile and desktop.

## Instructions for the AI Code Editor

Build the UIRevive frontend according to this specification.

Before coding: 1. Inspect the existing project files and identify the
framework and current structure. 2. Reuse the existing setup wherever
possible. 3. Plan the pages and reusable components. 4. Implement the
complete user journey with mock data.

While coding: - Keep components reusable and code readable. - Use
TypeScript types for the analysis report and issue data. - Make all
visible buttons and interactions functional. - Include loading, empty,
and validation states where relevant. - Do not add backend functionality
beyond the single Ollama API route. - Do not invent features outside the stated
scope. - Do not overwrite unrelated existing files or change project
configuration unnecessarily.

Prioritize a complete, polished, working frontend prototype over
unnecessary complexity.
